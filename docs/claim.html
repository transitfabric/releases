Claim credit: register your address

Register once. You sign a short message with a wallet, and we tie your GitHub account to that address, so points and any tips go to the right place. The bounty is still opening soon, and registering now is fine.

Signing moves no funds. This page never creates a transaction.

The page asks your wallet to sign a text message. It makes no network request, sends nothing anywhere, and stores nothing. Its wallet libraries are served from this site, not a third party. Use an address you made for testnet. A signed message can't spend anything, but there's no reason to link a wallet that holds real funds.

You must be 18 or older, or the age of majority where you live, whichever is higher. The message you sign says so, and accepts the Terms of Service and Privacy Policy. We never ask for your date of birth. Points and any awards go only to registrations signed with this message.

Registered before 17 November 2026? Your registration is kept, but it was signed without the age line, so it isn't eligible for awards until you sign again here with the same GitHub account and address.

A typed address is used instead of the wallet account. The page can't sign for it: sign the message from step 4 with btcli and paste the signature below the message.

4. Sign

Fill in steps 1 to 3 first. The page checks the signature and shows the result in step 5.

5. Send your claim

Open a prefilled Issue

The button opens a new Issue titled "Bounty registration" with these fields filled in. You need to be signed in to GitHub. Anyone can read it, and it holds only the message, your public address and the signature. If you want it private, paste the claim block into a private advisory instead.

Sign with btcli instead

If you'd rather not use a browser wallet, btcli can sign the same message. Type your address in step 2, fill in steps 1 and 3, and the command below fills in with your message. Paste the signature it prints in step 4. The message carries the same age attestation, so sign it only if it is true for you. This was checked with btcli 9.23.2. Run btcli wallet sign --help to see the options in your version.

btcli wallet sign --wallet-name <your wallet> --no-use-hotkey --message '<message from step 4>'
  • --no-use-hotkey signs with the wallet's coldkey, which btcli will ask you to unlock locally. Without it btcli asks which key to use. To sign with a hotkey, use --use-hotkey --hotkey <name>.
  • Get the address first (btcli wallet list, or your wallet) and put it in the message. The message must carry the address that signs. btcli prints it again as "Signer address".
  • Put the signature in the claim block as signature: 0x.... btcli prints it without the 0x, and either form is accepted.
  • Check it yourself with btcli wallet verify --message '<message>' --signature <sig> --address <ss58>. btcli signs the same way as the browser wallet, so both give a signature that the maintainers' verify-claim tool accepts.

Never type a seed phrase, a mnemonic or a private key into this page, an Issue or a chat. Signing happens in your wallet or in btcli on your own machine.
